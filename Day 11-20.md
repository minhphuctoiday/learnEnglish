## 📅 NGÀY 11: Giải thích Code/Thuật toán cho đồng nghiệp + Cấu trúc "phễu" (Funnel) của đoạn Introduction
 
**🎯 Mục tiêu:** Giải thích logic 1 đoạn code/thuật toán mạch lạc; nhận diện cấu trúc phễu (từ tổng quát → cụ thể) trong Introduction.
 
### 🗣️ A. Từ vựng giao tiếp
| Từ/Cụm từ | Nghĩa | Ví dụ |
|---|---|---|
| iterate over (v) | lặp qua | "This loop iterates over each element in the array." |
| return early | trả về sớm | "We return early if the input is invalid." |
| under the hood | về bản chất, ẩn bên trong | "Under the hood, it uses a hash map for lookup." |
| in a nutshell | tóm gọn lại | "In a nutshell, this function sorts and deduplicates the list." |
| time complexity | độ phức tạp thời gian | "This algorithm has O(n log n) time complexity." |
| trade-off (n) | sự đánh đổi | "There's a trade-off between speed and memory usage." |
| one thing to note | một điều cần lưu ý | "One thing to note is that this only works for sorted arrays." |
 
### 💬 B. Mẫu câu phản xạ
1. "Let me walk you through the logic step by step."
2. "Basically, what this function does is..."
3. "Under the hood, it..."
4. "The time complexity here is O(...), because..."
5. "In a nutshell, ..."
6. "One thing to note is that..."
**Mini-dialogue mẫu:**
> *"Let me walk you through this function. Basically, what it does is iterate over the input array and remove duplicates using a hash set. Under the hood, it uses O(1) lookup, so the overall time complexity is O(n). One thing to note is that it doesn't preserve the original order — that's a trade-off we accepted for performance."*
 
### 📄 C. Từ vựng & Cấu trúc CS — Cấu trúc "phễu" của Introduction
Introduction paper CS thường mở đầu **rất rộng**, rồi **thu hẹp dần** xuống vấn đề cụ thể, rồi đến đóng góp của paper. Đây là logic "phễu" (funnel).
 
| Từ khóa chuyển đoạn | Nghĩa | Vai trò |
|---|---|---|
| broadly speaking | nói rộng ra | Mở đầu (tổng quát nhất) |
| more specifically | cụ thể hơn | Thu hẹp phạm vi |
| in this context | trong bối cảnh này | Đặt vấn đề cụ thể |
| to this end | vì mục đích đó | Chuyển sang nêu đóng góp |
 
**Ví dụ minh họa cấu trúc phễu (3 câu, 3 tầng độ rộng):**
> *"Broadly speaking, natural language understanding has become central to many real-world applications. More specifically, question-answering systems require the ability to reason over multiple pieces of evidence. To this end, we propose a retrieval-augmented framework that..."*
 
### ✍️ D. Bài tập phản xạ
1. Chọn 1 hàm/thuật toán bạn từng viết → giải thích 5–6 câu dùng từ mục A, ghi âm.
2. Đọc đoạn Introduction của 1 paper thật → xác định chính xác câu nào là "tầng rộng nhất", câu nào là "tầng thu hẹp", câu nào là "câu đóng góp".
3. Tự viết 3 câu theo đúng cấu trúc phễu về 1 chủ đề bạn thích (không cần liên quan CS).

## 📅 NGÀY 12: Code Review — Đưa Feedback Xây dựng + Cách Trích dẫn Nghiên cứu khác
 
**🎯 Mục tiêu:** Đưa ra nhận xét code review lịch sự, rõ ràng; đọc hiểu các cụm từ trích dẫn (citation) thường gặp trong paper.
 
### 🗣️ A. Từ vựng giao tiếp
| Từ/Cụm từ | Nghĩa | Ví dụ |
|---|---|---|
| nitpick (n/v) | góp ý nhỏ nhặt | "Just a nitpick, but you could rename this variable." |
| readability (n) | tính dễ đọc | "Extracting this into a function would improve readability." |
| refactor (v) | tái cấu trúc code | "We should refactor this before merging." |
| consider (V-ing) | cân nhắc | "Consider adding a comment here." |
| LGTM (looks good to me) | trông ổn đấy | "LGTM, just one minor comment." |
| minor / major issue | vấn đề nhỏ/lớn | "This is a major issue — it could break production." |
 
### 💬 B. Mẫu câu phản xạ
1. "Just a small nitpick, but..."
2. "Have you considered...?"
3. "This looks good overall, but I'd suggest..."
4. "Could you explain why you chose this approach?"
5. "Nice work on this — one suggestion though..."
6. "LGTM, just one minor comment on naming."
### 📄 C. Từ vựng & Cấu trúc CS — Cách trích dẫn nghiên cứu khác
| Cụm trích dẫn | Nghĩa | Ví dụ |
|---|---|---|
| according to (X, Year) | theo (tác giả) | "According to Vaswani et al. (2017), self-attention..." |
| X et al. showed that | X và cộng sự đã chỉ ra rằng | "Smith et al. showed that pretraining improves accuracy." |
| as demonstrated by [X] | như được chứng minh bởi [X] | "As demonstrated by prior work, larger models tend to generalize better." |
| prior studies have found that | các nghiên cứu trước đã phát hiện rằng | |
 
**Ví dụ minh họa:**
> *"According to Vaswani et al., self-attention mechanisms can effectively model long-range dependencies without relying on recurrence. As demonstrated by subsequent work, this property makes Transformers particularly well-suited for parallelized training."*
 
### ✍️ D. Bài tập phản xạ
1. Viết 3–4 comment code review cho 1 đoạn pseudo-code (tự nghĩ lỗi hoặc điểm cần cải thiện).
2. Đọc 1 đoạn Related Work thật → liệt kê tất cả các cụm trích dẫn xuất hiện.
3. Ghi âm: đóng vai review code cho đồng nghiệp, dùng ít nhất 4 mẫu câu mục B.

## 📅 NGÀY 13: Thảo luận Kiến trúc Hệ thống (System Design) + Câu phức học thuật (Mệnh đề quan hệ & Bị động)
 
**🎯 Mục tiêu:** Thảo luận thiết kế hệ thống bằng câu phức hơn; đọc hiểu câu học thuật dùng mệnh đề quan hệ và thể bị động.
 
### 🗣️ A. Từ vựng giao tiếp
| Từ/Cụm từ | Nghĩa | Ví dụ |
|---|---|---|
| scalable (adj) | có khả năng mở rộng | "We need a system that can scale horizontally." |
| bottleneck (n) | điểm nghẽn | "The database could become a bottleneck under high load." |
| decouple (v) | tách rời (thành phần) | "It would be better to decouple these two services." |
| fault-tolerant (adj) | chịu lỗi tốt | "The system should be fault-tolerant." |
| single point of failure | điểm lỗi duy nhất | "This service is currently a single point of failure." |
| load balancing (n) | cân bằng tải | "We use load balancing to distribute traffic evenly." |
 
### 💬 B. Mẫu câu phản xạ
1. "We need a system that can scale horizontally."
2. "This component could become a bottleneck under high load."
3. "It would be better to decouple these two services."
4. "What happens if this service goes down?"
5. "We should design this to be fault-tolerant, so that..."
### 📄 C. Từ vựng & Cấu trúc CS — Câu phức học thuật
Paper CS dùng nhiều **mệnh đề quan hệ (which/that)** và **thể bị động (passive voice)** để câu súc tích và khách quan hơn.
 
| Cấu trúc | Ví dụ |
|---|---|
| ...a method **which/that** + V | "...a method which requires no manual annotation" |
| **is/are + V3** (passive) | "The dataset was collected from publicly available sources." |
| **have been + V3** | "Several techniques have been proposed to address this issue." |
 
**Ví dụ minh họa (câu phức nhiều tầng, điển hình trong Methodology):**
> *"The proposed architecture, which consists of an encoder and a decoder, is trained end-to-end using a large-scale dataset that was collected from publicly available sources."*
 
**Kỹ thuật đọc:** Khi gặp câu dài như trên, hãy tách thành các câu đơn:
- "The architecture consists of an encoder and a decoder." (mệnh đề quan hệ)
- "The architecture is trained end-to-end." (mệnh đề chính, bị động)
- "The dataset was collected from public sources." (mệnh đề quan hệ thứ 2, bị động)
### ✍️ D. Bài tập phản xạ
1. Mô tả 1 kiến trúc hệ thống (thật hoặc giả định) trong 5 câu, cố gắng dùng ít nhất 2 câu bị động + 1 mệnh đề quan hệ.
2. Tìm 1 câu phức trong Methodology của paper thật → tách nó thành 2–3 câu đơn theo kỹ thuật trên.
3. Ghi âm phần thảo luận kiến trúc hệ thống (60 giây).

## 📅 NGÀY 14: Tranh luận Kỹ thuật — So sánh Giải pháp + Related Work — Phân loại nghiên cứu (Taxonomy)
 
**🎯 Mục tiêu:** So sánh 2 giải pháp kỹ thuật một cách thuyết phục; đọc hiểu cách paper phân loại các nhóm nghiên cứu trước.
 
### 🗣️ A. Từ vựng giao tiếp
| Từ/Cụm từ | Nghĩa | Ví dụ |
|---|---|---|
| weigh the pros and cons | cân nhắc ưu nhược điểm | "Let's weigh the pros and cons of each option." |
| in terms of | về mặt | "In terms of performance, X is better." |
| at the cost of | đánh đổi bằng | "That comes at the cost of higher complexity." |
| justify (v) | biện minh, giải trình | "Can you justify why we should go with this approach?" |
| play devil's advocate | đóng vai phản biện | "Let me play devil's advocate here for a second." |
 
### 💬 B. Mẫu câu phản xạ
1. "Let's weigh the pros and cons of each option."
2. "In terms of performance, X is better, but in terms of cost, Y wins."
3. "That comes at the cost of..."
4. "Can you justify why we should go with this approach?"
5. "Let me play devil's advocate — what if we're wrong about...?"
### 📄 C. Từ vựng & Cấu trúc CS — Taxonomy trong Related Work
| Cụm từ | Nghĩa | Ví dụ |
|---|---|---|
| can be broadly categorized/classified into | có thể phân loại rộng thành | "Existing approaches can be broadly categorized into two groups." |
| fall into (X) categories | rơi vào (X) nhóm | "These methods fall into three main categories." |
| on one hand... on the other hand | một mặt... mặt khác | dùng khi so sánh 2 nhóm phương pháp |
 
**Ví dụ minh họa:**
> *"Existing approaches can be broadly categorized into two groups: rule-based methods, which rely on hand-crafted heuristics, and learning-based methods, which automatically learn patterns from data. On one hand, rule-based methods offer better interpretability; on the other hand, learning-based methods tend to generalize better to unseen cases."*
 
### ✍️ D. Bài tập phản xạ
1. Tranh luận SQL vs NoSQL (hoặc REST vs GraphQL) — viết 6 câu dùng từ vựng so sánh mục A.
2. Đọc đoạn Related Work thật → xác định paper chia nghiên cứu trước thành bao nhiêu nhóm, tiêu chí phân loại là gì.
3. Ghi âm bài tranh luận, chú ý ngữ điệu tự tin nhưng không gay gắt.

## 📅 NGÀY 15: Báo cáo Sprint Review + Ngôn ngữ Nguyên nhân-Kết quả trong học thuật
 
**🎯 Mục tiêu:** Trình bày kết quả sprint mạch lạc; đọc hiểu các cấu trúc chỉ nguyên nhân-kết quả trong paper.
 
### 🗣️ A. Từ vựng giao tiếp
| Từ/Cụm từ | Nghĩa | Ví dụ |
|---|---|---|
| deliverable (n) | sản phẩm bàn giao | "This sprint, we delivered three key features." |
| velocity (n) | tốc độ hoàn thành (Agile) | "Our velocity has improved compared to last sprint." |
| carry over (v) | chuyển sang sprint sau | "This task didn't finish, so it'll carry over." |
| retrospective (n) | buổi họp nhìn lại | "Let's discuss this in the retrospective." |
| milestone (n) | cột mốc | "We hit a major milestone this week." |
 
### 💬 B. Mẫu câu phản xạ
1. "This sprint, we delivered..."
2. "We didn't quite finish X, so it'll carry over to next sprint."
3. "Our velocity has improved compared to last sprint."
4. "One key takeaway from this sprint is..."
5. "Let's discuss the details in the retrospective."
### 📄 C. Từ vựng & Cấu trúc CS — Ngôn ngữ Nguyên nhân-Kết quả
| Cụm từ | Nghĩa | Vị trí trong câu |
|---|---|---|
| as a result | kết quả là | Đầu câu, sau dấu phẩy |
| consequently | do đó | Đầu câu |
| therefore | vì vậy | Đầu/giữa câu |
| due to / owing to | do, vì | Trước danh từ |
| this leads to | điều này dẫn đến | Giữa câu |
 
**Ví dụ minh họa:**
> *"Due to the increased model complexity, training time increases significantly. As a result, we adopt a more efficient sampling strategy, which consequently reduces the overall computational cost."*
 
### ✍️ D. Bài tập phản xạ
1. Viết báo cáo sprint review 5–6 câu (dùng deliverable, velocity, carry over...).
2. Đọc 1 đoạn Results/Discussion thật → tìm câu nguyên nhân-kết quả, xác định rõ đâu là nguyên nhân, đâu là kết quả.
3. Ghi âm báo cáo sprint (45–60 giây), luyện tốc độ nói vừa phải, rõ ràng.

## 📅 NGÀY 16: Xử lý Bất đồng quan điểm chuyên nghiệp + Cấu trúc Nhượng bộ-Phản bác (Concession)
 
**🎯 Mục tiêu:** Bất đồng quan điểm một cách lịch sự, chuyên nghiệp; đọc hiểu cấu trúc "tuy X đúng, nhưng Y" trong học thuật.
 
### 🗣️ A. Từ vựng giao tiếp
| Từ/Cụm từ | Nghĩa | Ví dụ |
|---|---|---|
| I hear what you're saying, but... | tôi hiểu ý bạn, nhưng... | |
| that's a fair point, however... | đó là điểm hợp lý, tuy nhiên... | |
| respectfully disagree | không đồng ý một cách tôn trọng | "I respectfully disagree because..." |
| see eye to eye | đồng quan điểm | "We don't seem to see eye to eye on this." |
| agree to disagree | thống nhất là sẽ không thống nhất | "Let's agree to disagree for now." |
 
### 💬 B. Mẫu câu phản xạ
1. "I hear what you're saying, but I still think..."
2. "That's a fair point, however..."
3. "I respectfully disagree, because..."
4. "We don't seem to see eye to eye on this — can we find middle ground?"
5. "Let's agree to disagree for now and revisit this later."
### 📄 C. Từ vựng & Cấu trúc CS — Nhượng bộ - Phản bác (Concession)
| Cụm từ | Nghĩa | Ví dụ |
|---|---|---|
| while (X is true) | trong khi (X đúng) | "While deep learning achieves strong results,..." |
| although / even though | mặc dù | "Although the model is accurate, it is computationally expensive." |
| that said | dù vậy | "That said, further validation is needed." |
| nonetheless | tuy nhiên, dù sao | "Nonetheless, the approach remains promising." |
 
**Ví dụ minh họa:**
> *"While deep learning models achieve impressive results on benchmark datasets, they often require large amounts of labeled data. Nonetheless, recent work has explored self-supervised techniques to reduce this dependency."*
 
### ✍️ D. Bài tập phản xạ
1. Roleplay bất đồng quan điểm về lựa chọn công nghệ (5 lượt thoại qua lại, tự viết cả 2 vai).
2. Tìm 1 câu dùng "while/although" trong paper thật → viết lại bằng "however" (đổi cấu trúc, giữ nguyên nghĩa).
3. Ghi âm đoạn roleplay bất đồng quan điểm.

## 📅 NGÀY 17: Giải thích Lỗi/Exception chi tiết + Định nghĩa Thuật ngữ trong Paper
 
**🎯 Mục tiêu:** Mô tả lỗi kỹ thuật chi tiết, có hệ thống; đọc hiểu cách paper định nghĩa thuật ngữ chuyên môn.
 
### 🗣️ A. Từ vựng giao tiếp
| Từ/Cụm từ | Nghĩa | Ví dụ |
|---|---|---|
| stack trace (n) | dấu vết ngăn xếp (lỗi) | "Looking at the stack trace, the error originates here." |
| exception (n) | ngoại lệ | "This throws a null pointer exception." |
| race condition | tình huống tranh chấp | "This is likely caused by a race condition." |
| memory leak | rò rỉ bộ nhớ | "We're seeing a memory leak in production." |
| trace through (v) | lần theo, truy vết | "Let me trace through the code step by step." |
 
### 💬 B. Mẫu câu phản xạ
1. "The error message says..."
2. "Looking at the stack trace, it seems like..."
3. "This is likely caused by a race condition."
4. "We're seeing a memory leak in production."
5. "Let me trace through the code step by step to find the root cause."
### 📄 C. Từ vựng & Cấu trúc CS — Định nghĩa Thuật ngữ
| Cụm từ | Nghĩa | Ví dụ |
|---|---|---|
| we define X as | chúng tôi định nghĩa X là | "We define accuracy as the ratio of correct predictions." |
| formally | về mặt hình thức | "Formally, we define the attention mechanism as..." |
| is defined as | được định nghĩa là | "Precision is defined as TP / (TP + FP)." |
| refers to | đề cập đến, chỉ về | "The term 'latency' refers to the time delay in processing." |
 
**Ví dụ minh họa:**
> *"Formally, we define the attention mechanism as a weighted sum over the input sequence, where the weights are learned during training and reflect the relative importance of each input element."*
 
### ✍️ D. Bài tập phản xạ
1. Mô tả 1 lỗi/exception thật bạn từng gặp trong 6 câu (dùng stack trace, root cause, trace through...).

3. Ghi âm phần mô tả lỗi, luyện phát âm "exception", "leak", "trace".

## 📅 NGÀY 18: Thảo luận Trade-off Kỹ thuật + Ngôn ngữ Giả thuyết (Hypothesis)
 
**🎯 Mục tiêu:** Thảo luận đánh đổi kỹ thuật một cách rõ ràng; đọc hiểu cách paper đặt ra giả thuyết nghiên cứu.
 
### 🗣️ A. Từ vựng giao tiếp
| Từ/Cụm từ | Nghĩa | Ví dụ |
|---|---|---|
| trade X for Y | đánh đổi X lấy Y | "We're trading speed for accuracy here." |
| diminishing returns | lợi ích giảm dần | "At some point, we hit diminishing returns." |
| optimal (adj) | tối ưu | "Given our constraints, this is the optimal choice." |
| constraint (n) | ràng buộc | "We have to work within tight time constraints." |
| optimize for (v) | tối ưu hóa cho | "What are we optimizing for — speed or cost?" |
 
### 💬 B. Mẫu câu phản xạ
1. "We're trading speed for accuracy here."
2. "At some point, we hit diminishing returns."
3. "Given our constraints, this is the optimal choice."
4. "What are we optimizing for — speed, cost, or accuracy?"
5. "There's no free lunch — every option has a downside."
### 📄 C. Từ vựng & Cấu trúc CS — Ngôn ngữ Giả thuyết (Hypothesis)
| Cụm từ | Nghĩa | Ví dụ |
|---|---|---|
| we hypothesize that | chúng tôi giả thuyết rằng | "We hypothesize that larger models generalize better." |
| assuming that | giả sử rằng | "Assuming the data is i.i.d., this bound holds." |
| it is likely that | có khả năng là | "It is likely that overfitting occurs at this stage." |
| we expect that | chúng tôi kỳ vọng rằng | "We expect that this trend will continue with scale." |
 
**Ví dụ minh họa:**
> *"We hypothesize that increasing the training data size will improve generalization performance, assuming the additional data is sufficiently diverse and representative of the target distribution."*
 
### ✍️ D. Bài tập phản xạ
1. Thảo luận 1 trade-off thật trong dự án của bạn (5 câu, dùng trade-off, constraint, optimize for...).
2. Đọc 1 câu giả thuyết trong Methodology → xác định đâu là hypothesis, đâu là assumption đi kèm.
3. Ghi âm đoạn thảo luận trade-off (45 giây).

## 📅 NGÀY 19: Đặt Câu hỏi Sâu trong Thảo luận Kỹ thuật + Đọc trọn 1 đoạn Related Work thật
 
**🎯 Mục tiêu:** Đặt câu hỏi đào sâu (probing questions) trong buổi thảo luận kỹ thuật; tóm tắt được logic của cả đoạn Related Work.
 
### 🗣️ A. Từ vựng giao tiếp
| Từ/Cụm từ | Nghĩa | Ví dụ |
|---|---|---|
| dig deeper | đào sâu hơn | "Let's dig deeper into why this happened." |
| what's the reasoning behind...? | lý do đằng sau...là gì? | "What's the reasoning behind this decision?" |
| could you elaborate on...? | bạn có thể nói rõ hơn về...? | "Could you elaborate on how this works?" |
| what led you to...? | điều gì khiến bạn...? | "What led you to choose this approach over X?" |
| have you looked into...? | bạn đã tìm hiểu...chưa? | "Have you looked into alternative solutions?" |
 
### 💬 B. Mẫu câu phản xạ
1. "What's the reasoning behind this decision?"
2. "Could you elaborate on how this works?"
3. "What led you to choose this approach over X?"
4. "Have you looked into alternative solutions?"
5. "What would happen if we scaled this up 10x?"
6. "How does this compare to what we discussed last time?"
### 📄 C. Bài tập đọc chuyên sâu — Tóm tắt logic đoạn Related Work
Đọc 1 đoạn Related Work **hoàn chỉnh** (4–6 câu) từ 1 paper thật (arXiv/ACL/CVPR...), sau đó trả lời:
1. Đoạn này chia nghiên cứu trước thành mấy nhóm? Tiêu chí phân loại là gì?
2. Câu nào chỉ ra **hạn chế** của nghiên cứu trước (however/but/fail to...)?
3. Câu cuối đoạn có nêu **paper này khác gì** so với nhóm đã liệt kê không (in contrast to/unlike/we differ in that...)?
### ✍️ D. Bài tập phản xạ
1. Chuẩn bị 5 câu hỏi "đào sâu" cho 1 buổi tech talk giả định (chủ đề tự chọn).
2. Thực hiện bài tập đọc chuyên sâu ở mục C với 1 đoạn Related Work thật.
3. Ghi âm 5 câu hỏi đã chuẩn bị, luyện ngữ điệu tò mò, cầu thị.

## 📅 NGÀY 20: ÔN TẬP TỔNG HỢP — Code Review + Tranh luận Kỹ thuật hoàn chỉnh + Đọc trọn Introduction & Related Work
 
**🎯 Mục tiêu:** Tổng hợp toàn bộ kỹ năng Ngày 11–19 vào 1 buổi luyện tập hoàn chỉnh.
 
### 🗣️ A. Ôn tập nhanh
> Xem lại bảng từ vựng mục A của Ngày 11→19 (khoảng 5 phút/ngày). Tự che nghĩa tiếng Việt, đoán lại nghĩa.
 
### 💬 B. BÀI TẬP TỔNG HỢP 1 — Roleplay Code Review + Tranh luận kỹ thuật (tự đóng cả 2 vai)
> **You:** "Nice work on this PR. Just a small nitpick — could you elaborate on why you chose a linked list here instead of an array?" *(Ngày 12, 19)*
> **Colleague:** "Sure, in terms of performance, insertion is O(1) here, but that comes at the cost of slower lookup." *(Ngày 14)*
> **You:** "That's a fair point, however, I hear this data grows rarely but is read very frequently — have you looked into using an array instead?" *(Ngày 16, 19)*
> **Colleague:** "Fair point. Let's weigh the pros and cons before deciding." *(Ngày 14)*
 
### 📄 C. BÀI TẬP TỔNG HỢP 2 — Đọc trọn Introduction + Related Work của 1 paper thật
1. Chọn 1 paper mới trên arXiv (cùng chủ đề bạn đã chọn ở Cấp độ 1 để có sự liên kết).
2. Vẽ **sơ đồ logic** (có thể vẽ tay hoặc mô tả bằng gạch đầu dòng) thể hiện:
   - Câu mở đầu rộng nhất (Background) → câu thu hẹp (Problem/Gap) → câu đóng góp (Contribution) *(cấu trúc phễu — Ngày 11)*
   - Related Work được chia thành mấy nhóm, tiêu chí gì *(taxonomy — Ngày 14)*
   - Paper này khác gì so với các nhóm đã liệt kê *(Ngày 19)*
3. Viết 1 đoạn tóm tắt bằng lời của bạn (5–6 câu) kết hợp cả Introduction lẫn Related Work.
### ✍️ D. Self-test cuối Cấp độ 2
Ghi âm 1 đoạn hội thoại 2 phút: giải thích code (Ngày 11) → nhận code review feedback (Ngày 12) → tranh luận nhẹ về giải pháp (Ngày 14, 16) → đặt 1 câu hỏi đào sâu (Ngày 19). Không dừng quá 3 giây mỗi lần ngập ngừng.
